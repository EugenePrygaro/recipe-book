# «Святковий стіл» — план реалізації

Мета: за кілька хвилин скласти меню на свято, отримати один список покупок і план «що й коли робити», щоб усе було готове до приходу гостей, а готувати вдвох було легко.

---

## 1. Сценарій користувача

1. **Нове свято.** Кнопка «Святковий стіл» → назва («Новий рік у нас»), дата й час подачі (31.12, 20:00), кількість людей (6). Тип свята підставляється з поточного сезону (`lib/season.js`), можна змінити.
2. **Меню.** Сайт пропонує структуру столу: 2 салати, 2 закуски, 1 гаряче, 1 гарнір (і місце під десерт). Кожен «слот» можна:
   - заповнити вручну зі списку страв (фільтр за категорією вже підставлений);
   - крутнути рулетку лише для цього слота (наявна рулетка з умовою «категорія + святкове»);
   - натиснути «Заповнити все» — рулетка по всіх порожніх слотах одразу.
   Внизу — підсумок: ккал і БЖУ на людину, загальний час на кухні.
3. **Порції.** Кожна страва автоматично масштабується на кількість гостей (є `fmtQty`), з коефіцієнтом «святкового столу»: коли страв багато, порція кожної менша (за замовчуванням 0,6 від звичайної, можна змінити).
4. **Покупки.** Одна кнопка — усе меню потрапляє в список покупок (наявний `collectItems` уже сумує однакові продукти). Продукти з «що є вдома» (`personal.pantry`) одразу відмічаються як наявні.
5. **План підготовки (таймлайн).** Від часу подачі назад: «за день», «вранці», «за 3 год», «за 1 год», «за 15 хв». Кожне завдання — з галочкою й іменем того, хто робить.
6. **Хто що робить.** Завдання розподіляються між вами двома: вручну або «порівну» одним натисканням. Кожен бачить свою частину й загальний прогрес.
7. **У день свята.** Головна показує банер «Сьогодні свято: 4 з 11 завдань» → відкриває план. Кожну страву можна відкрити в режимі готування.
8. **Після свята.** Оцінки страв (наявні зірочки), позначка «Приготували» для всього меню, свято зберігається в історії — наступного року «повторити меню».

## 2. Дані

### Нові сутності (спільні для вас двох)

```js
// rb:events  — hash: id → подія
{
  id: "e-…",
  title: "Новий рік у нас",
  kind: "newyear" | "easter" | "birthday" | "valentine" | "other",
  serveAt: 1798732800000,          // дата й час подачі
  guests: 6,
  portionFactor: 0.6,              // «святкова» порція
  menu: [                          // слоти
    { slot: "salad", recipeId: "b-caesar", servings: 4 },   // servings — після масштабування, можна правити
    { slot: "hot", recipeId: "b-plov", servings: 6 },
  ],
  tasks: [                         // таймлайн
    { id: "t1", recipeId: "b-plov", text: "Замаринувати м’ясо", at: -86400000, who: "tg:42", done: false },
  ],
  createdBy: "tg:42", createdAt, updatedAt
}
```

`at` — зсув від `serveAt` у мілісекундах (від’ємний — до подачі). Так план не ламається, якщо перенести час свята.

### Доповнення до рецептів (необов’язкові поля, редагуються у формі)

```js
{
  prepAhead: 24,        // скільки годин наперед можна приготувати (салатна заправка, маринад)
  servedCold: true,     // подається холодним — можна раніше
  steps: [ "…" ],       // як зараз; тривалість кроку витягується з тексту («варити 20 хвилин»)
}
```

Для вбудованих страв значення можна проставити один раз у `public/js/data/builtin.js`.

### Обмеження Vercel Hobby
Серверних функцій зараз 8 із 12 дозволених на тарифі Hobby. Тому все про свята — **одна** функція `api/events.js` (GET список, POST створити, PUT змінити, DELETE видалити, PATCH для швидких змін завдань), а дії розрізняються параметром `?action=`.

## 3. Алгоритми

### Склад меню за замовчуванням

| Гостей | Салати | Закуски | Гаряче | Гарнір | Десерт |
|---|---|---|---|---|---|
| 2 | 1 | 1 | 1 | 0–1 | 0–1 |
| 3–6 | 2 | 2 | 1 | 1 | 1 |
| 7+ | 3 | 3 | 2 | 1 | 1 |

Слот ↔ категорія: салат → «Салати», закуска → «Закуски», гаряче → «М’ясо», «Курка», гарнір → «Гарніри», «Паста».

### «Заповнити все»
Для кожного порожнього слота — рулетка серед страв категорії слота з пріоритетом:
1. позначка «На свято»;
2. висока оцінка (≥ 4);
3. «давно не готували»;
4. не більше однієї страви з тим самим основним продуктом (дві курки поспіль — ні), це видно з `lib/products.js`;
5. сумарний час активного готування не більше, ніж ви задали (наприклад, 4 години).

### Порції
`servings = ceil(guests × portionFactor × (1 / страв у категорії))`, мінімум — порція рецепта. Можна правити вручну.

### Таймлайн (зворотний відлік від подачі)
1. Для кожної страви визначити «готово не раніше» і «готово не пізніше»:
   - гаряче й гарнір — закінчити за 0–15 хв до подачі;
   - салати — зібрати за 30–60 хв, заправити в останні 15 хв;
   - те, що має `prepAhead`, — переносимо на «за день» або «вранці».
2. Тривалість кроків — з тексту (`/(\d+)[–-]?(\d+)?\s*(хв|хвилин|год)/`), решта кроків — по 5 хв.
3. Пакуємо завдання так, щоб дві духовки/конфорки не були потрібні одночасно (позначка обладнання — фаза 2).
4. Групи часу для показу: «за день», «вранці», «за 3 год», «за 1 год», «за 30 хв», «при подачі».

### Розподіл між двома
Жадібно: завдання в порядку часу, кожне — тому, в кого менше хвилин роботи в цьому часовому вікні. Завдання однієї страви по можливості — одній людині.

## 4. Інтерфейс

- **Список свят** — картки з датою, кількістю гостей і прогресом (`4/11`).
- **Редактор меню** — слоти з кнопками «вибрати» / «рулетка»; підсумок ккал на людину; «Заповнити все».
- **План** — вертикальний таймлайн з групами часу, аватарками «хто» й галочками; відсоток готовності; конфеті, коли все виконано (наявний `lib/confetti.js`).
- **Банер на головній** у день свята й за день до нього.
- **Сезонне оформлення** (вже є) підказує свято: «Святковий сезон: час планувати меню» → відкриває «Святковий стіл».

---

## 5. Етапи

| Етап | Що входить | Оцінка |
|---|---|---|
| **MVP** | подія, ручний вибір страв у слоти, масштабування порцій, «все меню в покупки», простий таймлайн за правилами вище, галочки | 1 ітерація |
| **2** | «Заповнити все» рулеткою, розподіл завдань між двома, банер у день свята, тривалості з тексту кроків, `prepAhead` у формі | 1 ітерація |
| **3** | історія свят і «повторити меню», друк меню, поділитися меню з гостями | 1–2 ітерації |

## 6. Масштабування ідеї

**Для вас двох**
- Нагадування від бота: «завтра свято — купити продукти», «розморозити м’ясо з вечора», «через годину — ставити гаряче». Потрібні Vercel Cron (на Hobby — щоденний запуск) + надсилання повідомлень ботом.
- Режим «готуємо разом»: на двох телефонах свої кроки, синхронізація галочок у реальному часі (опитування раз на кілька секунд або Upstash pub/sub).
- Бюджет свята: ціни продуктів (вручну або з останніх покупок), сума на гостя.
- Залишки: після свята — «що лишилось» → підказки страв наступного дня (наявний «З того, що є»).

**Для гостей**
- Публічне посилання на меню (без входу): гарна листівка з меню, алергени, «що принести».
- Опитування гостей: кожен відмічає, що не їсть (м’ясо, горіхи, лактоза) → меню перевіряється на конфлікти.
- Картки меню для друку (A6) і запрошення в тому самому стилі.

**Шаблони й контент**
- Шаблони свят: Новий рік, Різдво (12 страв), Великдень (паска, крашанки, шинка), день народження, пікнік, романтична вечеря на двох.
- Добірки «класичне святкове меню» з вбудованих страв і можливість додати свої.
- Експорт у календар (.ics) з таймлайном.

**Технічно**
- Штучний інтелект (за потреби, платно): «складіть меню на 6 людей, бюджет 2000 грн, один вегетаріанець» → чернетка меню з ваших страв.
- Офлайн уже є: план і список покупок свята кешуються так само, як решта даних.
- Якщо свят стане багато — перенести `rb:events` з одного hash в окремі ключі `rb:event:<id>` з індексом за датою.
